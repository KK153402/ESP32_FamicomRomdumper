# シリアルプロトコル / Serial Protocol

ESP32ファーム（v3）のシリアルコマンド仕様です。

| 項目 | 値 |
|---|---|
| ボーレート | 115200 bps、8N1 |
| 改行 | `\r`、`\n`、`\r\n` のいずれでも可 |
| 大文字・小文字 | 区別しない（`e 0` = `E 0`） |
| 数値 | アドレス・データは16進（`$` や `0x` は付けない）、個数は10進 |
| 文字コード | 応答はすべてASCII |

---

## 起動時の状態

| 信号 | 状態 | 意味 |
|---|---|---|
| `BUS_EN_N` | 1 | U1〜U4、U9の出力がHi-Z。カセット側はプル抵抗で非アクティブに保持される |
| `OE_DATA_N` | 1 | U5、U6（データ書き込み用）の出力がHi-Z |
| 制御線 | 非アクティブ | M2 = 0、/ROMSEL = 1、R/W = 1、/RD = 1、/WR = 1、/A13 = 1 |

**カセットを読む前に必ず `E 0` を送ること。**

---

## コマンド一覧

### バス・信号の操作

| コマンド | 引数 | 動作 | 応答例 |
|---|---|---|---|
| `E n` | 0 / 1 | `BUS_EN_N` の設定。0 = バス有効、1 = Hi-Z | `BUS_EN_N = 0 (enabled)` |
| `A cccc pppp` | CPUアドレス（15 bit）、PPUアドレス（14 bit） | 595にアドレスを出力して保持する | `CPU A=$7FFF  PPU A=$3FFF` |
| `C name n` | 制御線名、0 / 1 | 制御線を個別に設定。名前は `M2` `ROMSEL` `RW` `RD` `WR` `A13` | `M2 = 1` |
| `I` | なし | 制御線をすべて非アクティブに戻す | `control lines idle` |

`A` のCPUアドレスは下位15 bit（A0〜A14）です。A15はコネクタに出ておらず、/ROMSELがその役割を担います。`$8000`〜`$FFFF` を読むときは `A` に `$0000`〜`$7FFF` を指定し、/ROMSELをLにします（`P` コマンドは自動でこれを行う）。

### 読み出し

| コマンド | 引数 | 動作 | 応答例 |
|---|---|---|---|
| `R` | なし | 165に現在のデータバスをロードして読む | `CPU D=FF  PPU D=FF` |
| `G` | なし | CIRAM A10、CIRAM /CE を読む | `CIRAM_A10=1  CIRAM_CE_N=1` |
| `V` | なし | CPUの割り込みベクタ（`$FFFA`〜`$FFFF`）を読んで判定 | 下記 |
| `P aaaa [n]` | 開始アドレス（`$8000`〜`$FFFF`）、バイト数（省略時16） | PRG-ROMの16進ダンプ | `8000: 78 D8 A9 10 …` |
| `H aaaa [n]` | 開始アドレス（`$0000`〜`$1FFF`）、バイト数（省略時16） | CHR-ROMの16進ダンプ | `0000: 03 0F 1F 1F …` |
| `M` | なし | ミラーリング判定 | 下記 |
| `D` | なし | 全領域のバイナリダンプ（PC側スクリプト用） | 下記 |

### 設定

| コマンド | 引数 | 動作 |
|---|---|---|
| `S n` | µs（1以上） | シフトクロックの半周期。既定値1 µs。接点が不安定なときに大きくする |
| `?` | なし | コマンド一覧を表示 |

---

## `V`：ベクタ読み出し

```
NMI   $FFFA = $8082 [OK]
RESET $FFFC = $8000 [OK]
IRQ   $FFFE = $FFF0 [OK]
```

6502は電源投入時に `$FFFC`/`$FFFD` を読んで開始番地とするため、正常なカセットなら値は必ず `$8000` 以上になります。外部の正解データなしに、回路が正しく読めているかを自己判定できます。

---

## `M`：ミラーリング判定

PPUアドレスを `$2000`、`$2400`（PA10 = 1）、`$2800`（PA11 = 1）の順に出力し、カセットが返すCIRAM A10を読みます。

| CIRAM A10 の追従先 | 判定 | 表示 |
|---|---|---|
| PA10 | 垂直ミラー | `VERTICAL (follows PA10)` |
| PA11 | 水平ミラー | `HORIZONTAL (follows PA11)` |
| どちらでもない | 1画面 / 4画面 / 配線異常 | `UNKNOWN` |

NROMのカセットでは、CIRAM A10はカセット基板上でPA10かPA11に直結されているため、この方法で判定できます。

---

## `D`：バイナリダンプ

PC側スクリプト（`tools/dump_nes.py`）が使うコマンドです。シリアルモニタで送ると、バイナリがそのまま表示されて画面が乱れます。

### 送信形式

```
DUMP prg=<PRGサイズ> chr=<CHRサイズ> mir=<V|H|?>\n
<PRGデータ（prgバイト）>
<CHRデータ（chrバイト）>
\n
END crc=<8桁16進>\n
```

| フィールド | 内容 |
|---|---|
| `prg` | 16384 または 32768 |
| `chr` | 8192（固定） |
| `mir` | `V`（垂直）、`H`（水平）、`?`（判定不能） |
| `crc` | PRGデータとCHRデータを連結したものの CRC-32（IEEE 802.3、zlibと同一） |

### ファーム内の処理

1. `$8000`〜`$FFFF` の32 KBを読んでRAMに格納
2. PPU `$0000`〜`$1FFF` の8 KBを読んでRAMに格納
3. ミラーリングを判定
4. PRGの前半16 KBと後半16 KBを比較し、一致すれば16 KB品（NROM-128）と判定。この場合は `$C000`〜`$FFFF` 側の16 KBを送る
5. CRC-32を計算して送信

NROM-128のカセットはA14を使わないため、`$8000`〜`$BFFF` と `$C000`〜`$FFFF` に同じ内容が見えます。

所要時間は、読み出し約5秒、転送約4秒です（32 KB + 8 KB の場合）。

---

## PC側の処理（`tools/dump_nes.py`）

1. ポートを開く（DTR/RTSをLにして、ESP32の自動リセットを避ける）
2. `E 0` を送る
3. `D` で1回目のダンプ。CRCを照合
4. `D` で2回目のダンプ。CRCを照合
5. `E 1` を送る
6. 2回の結果（PRG、CHR、ミラーリング）が完全一致した場合のみ、iNESヘッダを付けて保存

### 生成するiNESヘッダ（16バイト）

| オフセット | 値 | 内容 |
|---|---|---|
| 0〜3 | `4E 45 53 1A` | `"NES"` + `$1A` |
| 4 | PRGサイズ ÷ 16384 | 1 または 2 |
| 5 | CHRサイズ ÷ 8192 | 1 |
| 6 | `$01`（垂直）/ `$00`（水平） | bit 0 = ミラーリング、上位4 bit = マッパー番号下位（0） |
| 7 | `$00` | マッパー番号上位（0） |
| 8〜15 | `$00` | 未使用 |

---

## 終了コード（`dump_nes.py`）

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 引数エラー |
| 2 | 2回のダンプが一致しない |
| 例外終了 | 応答なし、CRC不一致、受信バイト不足 |
