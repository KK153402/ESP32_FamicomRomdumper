# 立ち上げ手順 / Bring-up Guide

部品を実装した基板を、はじめてカセットを吸い出してMesenでゲームが起動するところまで確認する手順です。

**カセットを挿すのはStep 4からです。** Step 0〜3で、アドレス線・制御線・データ線を回路単体で確認します。いきなりカセットを挿すと、読めなかったときに原因がカセットなのか回路なのか切り分けられません。

配線の詳細は [hardware.md](hardware.md)、コマンドの詳細は [protocol.md](protocol.md) を参照してください。

---

## 必要なもの

| 種類 | 内容 |
|---|---|
| 工具 | テスタ（電圧・導通・抵抗） |
| 部品 | 1 kΩ抵抗 1本（Step 3でジャンパー線の代わりに使う。無くても可） |
| カセット | **Mapper 0（NROM）のファミコンカセット**。スーパーマリオブラザーズ（PRG 32 KB）を推奨 |
| PCソフト | VS Code + PlatformIO、Python 3、MesenCE |

### 最初のカセットにNROMを使う理由

NROMはバンク切替がないので、アドレスを出して読むだけで全領域が読めます。MMC1やMMC3のカセットは、専用レジスタへの書き込みなしでは全領域を読めず、最初の確認には向きません。

PRGが32 KBのカセット（スーパーマリオブラザーズ等）は、アドレス線をA14まですべて使います。16 KB品（ドンキーコング等）はカセット側でA14を使わないため、A14の配線不良を見逃します。

## Step 0：通電前の確認

ESP32ボードを挿さずに、テスタで確認します。

| 確認 | 合格条件 |
|---|---|
| `+5V`–GND、`+3.3V`–GND、`VCC_CART`–GND の抵抗 | 短絡していない（数百Ω以上） |
| `+5V`–`+3.3V` の抵抗 | 短絡していない |
| IC 12個の1番ピンの向き | シルクと一致 |
| U10〜U12（74LVC1T45、SOT-23-6）の向き | 逆だとVCCA/VCCBが入れ替わって壊れる |

---

## Step 1：ファームの書き込み

1. VS Codeで `firmware/` フォルダを開く（`platformio.ini` のあるフォルダ）
2. SW1 OFF、カセット未挿入でESP32ボードをUSB接続
3. PlatformIOのUpload（→）を実行

`Connecting......` で止まる場合は、ESP32ボードのBOOTボタンを押しながら書き込みを開始してください。

書き込み後、Serial Monitor（コンセントのアイコン）を開くと以下が表示されます。表示されなければENボタンを1回押してください。

```
Famicom Dumper v3 (bit-bang + dump). BUS_EN_N=1 (Hi-Z) at boot
```

`?` を送るとコマンド一覧が表示されます。

---

## Step 2：電源の確認

テスタで測ります。

1. SW1 OFFで、J1:30（`VCC_CART`）が0 V
2. **このとき各ICのVCC（U1〜U9）は5 Vのまま**であること。0 Vになるなら、カセット電源が独立レールになっていない
3. SW1 ONで、J1:30が5 V、LED D1が点灯
4. U10〜U12のVCCAが3.3 V、VCCBが5 V

---

## Step 3：アドレス線の確認（カセット未挿入）

> ⚠️ **ESP32の起動直後はバスがHi-Z（`BUS_EN_N` = 1）です。最初に必ず `E 0` を送ってください。**
> Hi-Zのままだと、カセット側の線はプル抵抗の電圧になり、コマンドを送っても変化しません。書き込み直しやリセットのたびに `E 0` が必要です。

J1のはんだ面をテスタで測ります（コネクタの中は奥まっていてプローブが当てにくいため）。

```
E 0
A 5555 1555
A 2AAA 2AAA
```

アドレス29本（J1のピン2〜13、33〜35、19〜25、50〜56）が、2つのパターンで0 V / 5 Vが反転すれば合格です。この2パターンで、固着・隣接ピンのブリッジ・ビットの取り違えをすべて検出できます。

| コマンド | 出力されるパターン |
|---|---|
| `A 5555 1555` | A0、A2、A4 … が5 V、A1、A3 … が0 V |
| `A 2AAA 2AAA` | 上の反転 |

出力は次のコマンドを送るまで保持されるので、1本ずつ測って構いません。

---

## Step 4：制御線の確認（カセット未挿入、SW1 ON）

```
E 0
C M2 1       → J1:32 = 5 V      C M2 0      → 0 V
C ROMSEL 0   → J1:44 = 0 V      C ROMSEL 1  → 5 V
C RW 0       → J1:14 = 0 V      C RW 1      → 5 V
C RD 0       → J1:17 = 0 V      C RD 1      → 5 V
C WR 0       → J1:47 = 0 V      C WR 1      → 5 V
C A13 0      → J1:49 = 0 V      C A13 1     → 5 V
I
```

**0 Vに落ちることを必ず確認してください。** `E 0` を忘れていると、M2以外の5本はプル抵抗で5 Vのままなので、正常に見えてしまいます（M2だけはプルダウンなので0 Vのままになり、異常に見えます）。

---

## Step 5：データ線の確認（カセット未挿入、SW1 ON）

> ⚠️ **SW1をONにしてから行ってください。** データ線のプルアップは `VCC_CART` に接続されているので、SW1 OFFではデータ線が浮き、テスタでは2〜3 V程度の意味のない値が見えます。

```
R   → CPU D=FF  PPU D=FF
G   → CIRAM_A10=1  CIRAM_CE_N=1
```

### ビット順の確認（任意）

1 kΩ抵抗の片足をGND（J1:1か16）に、もう片足をJ1の各データピンのはんだ面に当てて `R` を送ります。

| 当てるピン | 期待値 |
|---|---|
| 43（CPU D0） | `CPU D=FE` |
| 36（CPU D7） | `CPU D=7F` |
| 26（PPU D0） | `PPU D=FE` |
| 57（PPU D7） | `PPU D=7F` |

1 kΩを使うと、10 kΩのプルアップとの分圧で 5 V × 1 / (10 + 1) = 0.45 V になり、HCT165のVIL（0.8 V）を下回るので確実にLと読まれます。直接GNDに短絡させるのと違い電流が約0.45 mAに制限されるので、当てる場所を間違えても壊れません。

この確認を省略しても、Step 6のカセットの中身でビット順を確認できます。

---

## Step 6：カセットの読み出し

### カセットの向き

**ラベル面が、J1のピン1〜30側**です。ラベル面を手前にして端子を下に向けたとき、左端がピン1（GND）、右端がピン30（+5V）です。

逆に挿すと電源とGNDが違うピンに入ってカセットを壊すおそれがあるので、初回は以下で確認してください。

1. **カセット側**：テスタの導通モードで、ラベル面の左から1本目と16本目を当てる → 導通あり（どちらもGND）
2. **基板側**：J1のピン1のパッド（四角いパッド）がある列を確認する。カセットのラベル面をその列の側に向ける

### 挿入手順

```
E 1 → SW1 OFF → カセット挿入 → SW1 ON → E 0
```

SW1 ONでLED D1が点灯することを確認します。点灯しない、またはUSBの電流が急増する場合は、すぐにSW1をOFFにして向きを確認し直してください。

### 読み出し確認

```
V
P 8000 16
M
H 0000 16
```

スーパーマリオブラザーズでの実測値：

```
NMI   $FFFA = $8082 [OK]
RESET $FFFC = $8000 [OK]
IRQ   $FFFE = $FFF0 [OK]
8000: 78 D8 A9 10 8D 00 20 A2 FF 9A AD 02 20 10 FB AD
CIRAM A10: base=0 PA10=1 PA11=0 -> VERTICAL (follows PA10)
0000: 03 0F 1F 1F 1C 24 26 66 00 00 00 00 1F 3F 3F 7F
```

| コマンド | 確認していること | 合格の目安 |
|---|---|---|
| `V` | CPUアドレス線、/ROMSEL、M2、CPUデータ線 | 3行とも `[OK]`（$8000以上） |
| `P 8000 16` | ビット順 | 先頭が `78 D8`（SEI、CLD）。ほとんどのファミコンソフトはこの2命令で始まる |
| `M` | PPUアドレス線（A10/A11/A13）、CIRAM A10 | カセットの仕様どおり（SMBはVERTICAL） |
| `H 0000 16` | PPUアドレス線、PPU /RD、PPUデータ線 | `FF` 以外の値が混ざる |

### カセットを抜くとき

```
E 1 → SW1 OFF → カセットを抜く
```

`E 1` を忘れて抜くと、電源の落ちたカセットにアドレス線の5 Vが加わります。

## Step 7：PCへダンプして `.nes` を作る

### Python環境の準備（初回のみ）

```
python -m venv ESP32_Famicom
ESP32_Famicom\Scripts\activate
pip install pyserial
```

VS Codeで「Pythonパッケージをグローバル環境にインストールしている可能性があります」と通知が出ることがありますが、プロンプトの先頭に `(ESP32_Famicom)` と出ていれば仮想環境に入っているので無視して構いません。

### ダンプ

1. **PlatformIOのシリアルモニタを閉じる**（ポートを占有するため）
2. カセットを挿してSW1 ON
3. 実行：

```
python tools/dump_nes.py COM5 smb.nes
```

`COM5` はESP32のポート番号に置き換えてください。スクリプトが開始時に `E 0`、終了時に `E 1` を自動で送るので、手動操作は不要です。

```
BUS_EN_N = 0 (enabled)
pass 1: PRG 32KB  CHR 8KB  mirror=V  CRC32=D445F698  (11.5s)
pass 2: CRC32=D445F698
BUS_EN_N = 1 (Hi-Z)
OK: smb.nes (40976 bytes)  PRG+CHR CRC32=D445F698
```

4. 終わったらSW1 OFF → カセットを抜く

スクリプトは2回ダンプして完全一致した場合のみ保存します。一致しない場合は、カセットの端子を無水エタノールと綿棒で清掃してから挿し直してください（消しゴムは金メッキを削るので使わない）。

> 吸い出したROMファイルは、このリポジトリのフォルダの外に保存することを勧めます。誤ってGitHubにアップロードしないためです。

---

## Step 8：Mesenで起動

1. [MesenCE](https://github.com/nesdev-org/MesenCE)（Mesen 2の後継）をダウンロードする。Windows 10/11はネイティブ版（.NETランタイム不要）でよい
2. 起動して、`smb.nes` をウィンドウにドラッグ＆ドロップ
3. タイトル画面が出て、1-1がプレイできれば完了

**ゲームが最後まで正しく表示されることが、ダンプが1バイトも化けていないことの最終確認です。** 背景やキャラクターの絵が崩れていないか、しばらく遊んで確認してください。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| コマンドを送っても電圧が変わらない | `E 0` を送っていない | 起動・リセットのたびに `E 0` |
| M2だけ5 Vにならない | 同上（M2だけプルダウンのため目立つ） | `E 0` |
| データ線が2〜3 V | SW1 OFFでプルアップが無効 | SW1 ON |
| `R` が常に `00 00` | SW1 OFF、またはU10の向き・VCCA/VCCB | SW1確認、U10確認 |
| `R` が常に `FF FF`（GNDに落としても不変） | /PL（GPIO33）、165のCLK INH（ピン15）の未接続 | はんだ確認 |
| `R` が `FF FE` | 165の先頭ビット欠落（ハードウェアSPI MODE0使用時） | v2以降のファーム（ビットバング）を使う |
| `V` で `$FFFF` | `E 0` 忘れ、端子の汚れ、差し込みが浅い | `E 0`、端子清掃、挿し直し |
| `V` の値が毎回変わる | 接点不良、ノイズ | 挿し直し、`S 5` でシフトクロックを遅くする |
| 値は安定しているが `78 D8` にならない | アドレス線の不良、ビット順 | Step 3・5をやり直す |
| `could not open port` | シリアルモニタが開いたまま | モニタを閉じる |
| `NG: 2回のダンプが一致しません` | 接点不良 | 端子清掃・挿し直し |
| `CRC mismatch` | USBシリアル転送の化け | ケーブル交換、USBハブを避ける |
| 書き込みが `Connecting......` で止まる | ESP32が書き込みモードに入らない | BOOTボタンを押しながら書き込み |
